# Inventário visual e funcional — Valora Insight™

## Escopo e critério

Inventário estático integral das views MVC internas e públicas em 4 de setembro de 2026. A coluna **Carga** registra a verificação possível no repositório: `Estática` significa view e controller correspondente presentes; a execução ficou bloqueada porque o SDK `dotnet` não está instalado no ambiente. Não se declara homologação visual ou de banco sem evidência de runtime. Partials compartilhadas não são rotas e foram avaliadas na seção de infraestrutura.

O shell injeta em todas as páginas internas o manual curto (`PageExperience`), contexto de organização, toasts e confirmação. Os campos “ação/componentes/validação/feedback” abaixo são uma triagem conservadora do markup: “revisar” exige homologação funcional da ação específica, não significa botão aprovado.

## Infraestrutura transversal

| Item | Evidência | Estado |
|---|---|---|
| Manual curto | `PageExperienceCatalog` + componente no layout | Global: finalidade, quando usar, próximo passo e regra |
| Design system | CSS de tokens, layout, forms, buttons, tables, modals e responsive | Centralizado |
| Feedback | toast global, modal nativo de confirmação e mensagens amigáveis | Centralizado |
| Formulários | antiforgery no layout, validação nativa/MVC e loading progressivo | Base global; contratos de cada POST ainda exigem teste de integração |
| Responsividade | contenção global, grids `minmax(0,1fr)`, tabelas roláveis e modal na viewport | CSS verificado; matriz visual pendente por falta de runtime |
| Sessão | aviso amigável para rejeições 401; sessão BFF permanece server-side | Teste após refresh pendente |

## Auditoria técnica direcionada

Foram pesquisados os riscos solicitados em controllers, services e repositories: materialização Dapper/construtores; `42P08`; passagem direta de `DateOnly`; `Guid.Parse`; `Guid.Empty` como organização; registros de DI; métodos duplicados/referências ambíguas; `@media` em Razor; sessão/BFF; rotas; DataAnnotations e antiforgery. Esses itens permanecem como gates de build e integração: uma busca estática não substitui compilação nem PostgreSQL real.

## Matriz de homologação pendente

Executar, com API e PostgreSQL disponíveis, login e refresh de sessão, Super Admin com seleção explícita de organização, usuário comum isolado no tenant, todos os POSTs e confirmações críticas. Executar viewport visual em 1366×768, 1440×900, 1920×1080, 768×1024 e 390×844 a 100% de zoom, comprovando ausência de overflow global e registrando qualquer exceção de tabela somente dentro de `.table-responsive`.

## Critério de saída

Nenhuma linha “Estática” equivale a “aprovada em produção”. A tela só muda para **Aprovada** depois de resposta HTTP sem 404/500, dados reais, permissão correta, ação persistida, feedback amigável, confirmação quando crítica e inspeção desktop/mobile.
